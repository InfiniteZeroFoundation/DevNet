## Background

`DINTaskCoordinator.autoCreateTier1AndTier2` and `createAuditorsBatches` build the validator pool by calling `_activeAggregatorPool` / `_activeAuditorPool` **at call time**, after the batch-creation seed is already public. A validator can unstake between the seed lock and the batch-creation call. This changes the active-pool size and causes Fisher-Yates to re-roll the entire batch assignment for every other participant — not just the leaving validator's own seat.

The fix is already available in the codebase: `_assignFreshSubgroup` (the dispute re-eval draw, landed in PR #171) shuffles a **fixed per-GI registration list** with the locked seed and skips inactive entries while filling seats. An unstake under that scheme only drops the leaver's own slot; everyone else's assignment is already committed.

This is a **distinct gap** from the re-roll-by-declining-to-lock residual tracked in issue #178. It requires no GI-abort design (issue #222) as a prerequisite.

## Implementation

### 1. Aggregator batch creation

In `autoCreateTier1AndTier2`:

- Replace the `_activeAggregatorPool()` call with `dinAggregators[_GI]` (the fixed list of aggregators who registered for this GI).
- Shuffle `dinAggregators[_GI]` using the locked seed (already available: `aggSeed[_GI]`), following the same pattern as `_assignFreshSubgroup`.
- Walk the shuffled list to fill T1/T2 seats, **skipping** any entry where `!stake.isValidatorActive(addr)` — this is the same skip-inactive pattern `_assignFreshSubgroup` uses.
- An inactive validator (unstaked after registration) gets no seat; everyone else keeps theirs.

### 2. Auditor batch creation

Apply the same change in `createAuditorsBatches`:

- Replace `_activeAuditorPool()` with the per-GI registered auditor list.
- Shuffle with `auditSeed[_GI]`, skip inactive entries.

### 3. No change to shuffle helper

The existing `_shuffleAddressArray(arr, seed)` helper (task_240926_18 Part B) already takes an explicit seed. No new helper needed.
