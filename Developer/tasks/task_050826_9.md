### 1. New contract: `foundry/src/DinFairLaunchDistributor.sol`

Transparent Proxy pattern, matching the existing platform contracts exactly — same shape as `DinValidatorStake.sol`/`DinToken.sol` (`Initializable`, `OwnableUpgradeable`, `initialize()` instead of constructor args) and the same deploy pattern as `foundry/script/DeployPlatform.s.sol` (`Upgrades.deployTransparentProxy(...)`).

**Important implementation note on vesting:** the earlier design conversation described this as "OZ `VestingWallet`-style." Don't actually deploy OZ's `VestingWallet`/`VestingWalletCliff` — those are **single-beneficiary** contracts (one instance per recipient), which would mean deploying N contracts for N validators. What's wanted is **one** distributor contract holding a `mapping(address => VestingPosition)` internally, reusing OZ's linear-vesting *math* (cliff, then linear release to `cliff + duration`) but not the OZ contract class itself. `lib/openzeppelin-contracts/contracts/utils/cryptography/MerkleProof.sol` is available and should be used as-is for proof verification.

**State & functions (design intent — adjust as needed, but flag any deviation in your PR description):**

- `initialize(address dinToken_, address treasuryAdmin_, uint64 cliffDuration_, uint64 vestingDuration_)` — `dinToken_`/`treasuryAdmin_` addresses, cliff/vesting durations in seconds. `treasuryAdmin_` becomes `owner()`. **No Gnosis Safe exists yet for testnet** — pass an EOA (Umer's or a test wallet) as `treasuryAdmin_` for now; document in NatSpec that this should point at a Gnosis Safe once one exists, consistent with DD-3's "multisig = treasury only" model. Don't block on a Safe existing.
- `deposit(uint256 amount)` — `onlyOwner`, pulls `amount` via `transferFrom(msg.sender, address(this), amount)` (treasury pre-approves), increments `totalFunded`. This is the "funded once from treasury" step — not per-user minting, `DinToken.mint` stays `onlyCoordinator` and is untouched.
- `setRoot(bytes32 root_)` — `onlyOwner`, settable only **before** `openClaims()` has been called (so a snapshot can be corrected pre-launch); revert with a custom error after claims open, so a root can't be swapped out from under people who already hold valid proofs.
- `openClaims()` — `onlyOwner`, one-shot (revert if already open), freezes the current root, records `vestingStart = block.timestamp` (the vesting clock starts here, not at admin's leisure), sets `claimsOpen = true`.
- `claim(uint256 index, uint256 totalAmount, bytes32[] calldata proof)` — `nonReentrant` (reuse `ReentrancyGuardTransient`, same as `DinCoordinator`/`DinValidatorStake`). Requires `claimsOpen`. Leaf shape: `keccak256(bytes.concat(keccak256(abi.encode(index, msg.sender, totalAmount))))` (standard double-hashed leaf, avoids second-preimage issues) verified against the frozen root. One-time per address (revert on repeat). Creates the caller's `VestingPosition{total: totalAmount, claimed: 0}` and immediately releases whatever's already vested as of `block.timestamp` (0 if still pre-cliff). Increments `totalClaimedPrincipal` by `totalAmount` (the *full* allocation, not just what's released yet — needed for the sweep invariant below).
- `release()` — `nonReentrant`, callable by anyone for their own position, any number of times. No proof needed (position already exists post-`claim`). Releases `vestedAmount(msg.sender) - position.claimed`.
- `vestedAmount(address account) public view returns (uint256)` — standard cliff+linear formula: `0` before `vestingStart + cliffDuration`; `total` at/after `vestingStart + vestingDuration`; linear interpolation between.
- `sweepUnclaimed(address to)` — `onlyOwner`, callable only after a deadline (`vestingStart + vestingDuration + sweepGracePeriod` — pick a reasonable grace period, e.g. 30 days, and make it a constant or initializer param, your call). Sweeps `totalFunded - totalClaimedPrincipal` (i.e., allocations nobody ever claimed at all — not unreleased-but-claimed vesting, which stays claimable by its owner indefinitely) back to `to`. Addresses Q7's griefing concern (unclaimed allocations shouldn't sit stranded forever).
- Custom errors throughout, not `require(cond, "string")` — matches the gas-optimization convention already being applied elsewhere in `foundry/src` (see P3-6.3a in `ROADMAP.md`).
- Full NatSpec (`@notice`/`@param`/`@return`) on every public/external function — matches P3-6.3b convention.

### 2. Deploy script

New `foundry/script/DeployFairLaunchDistributor.s.sol`, following `DeployPlatform.s.sol`'s exact pattern (`Upgrades.deployTransparentProxy`, `console.log` the proxy address). Reads the existing `DinToken` proxy address the same way `DeployPlatform.s.sol`'s later steps do. Don't wire this into `dincli import-deployments` — that's Python/dincli tooling, outside your lane; just get the contract deployable and log the address clearly enough that someone else can wire it up later.

### 3. Tests (`foundry/test/`)

Foundry tests using a **hand-built test Merkle tree** (4–8 addresses is enough) — this is what makes the contract testable end-to-end on local anvil without waiting on the real eligibility pipeline (see below). Cover at minimum:
- Happy path: `deposit` → `setRoot` → `openClaims` → `claim` (0 vested pre-cliff) → warp past cliff → `release()` releases the right linear fraction → warp past full duration → `release()` drains remainder.
- Invalid proof rejected; double `claim()` rejected; `setRoot` after `openClaims()` rejected; `openClaims()` called twice rejected.
- `sweepUnclaimed` before deadline rejected; after deadline, sweeps exactly the never-claimed portion, leaves already-claimed-but-unvested positions untouched.
- Reentrancy guard present on `claim`/`release`.
- Funding invariant: can't claim more in total than `totalFunded`.

## Explicitly out of scope for this task (and why)

**Eligibility computation** — deciding *who* qualifies and *how much* they get, and turning that into the `(address, amount)` list that generates the Merkle root — is **not** part of this task. Two reasons:

1. It's off-chain scripting/aggregation, not contract work — outside your Solidity/Foundry lane.
2. Umer's call (Aug 5 2026): fair-launch distribution should sit in **P4**, and the eligibility snapshot should be computed off the **on-chain indexer** (P4-IDX1/P4-IDX2 — also your work, `Developer/ROADMAP.md`) rather than a raw RPC-log script, once that indexer exists. The snapshot script itself would then be run by "authority" (i.e., executed by whoever holds the `treasuryAdmin_` key/Safe — an operational script, not on-chain logic) to compute the list and call `setRoot()`.

That means this task's tests use a **hand-built** test tree specifically so the contract can be built and verified now, without waiting on the indexer. The real indexer-backed eligibility script is the next slice in this line of work — flag it as such (don't start it) once this task is done, same convention as prior deferred-slice tasks in this repo.
