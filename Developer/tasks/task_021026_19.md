# Part A — #201 Part A: EIP-170 budget, CI gate, `DINTaskCoordinator` under budget — PR 1, commit 1

## Design: shrink inside the same contract

Don't add a library, a second contract, or a deploy step. All three levers below were prototyped twice against `6ccc28c`: once for the source plan, and once independently in the PR #209 review. Runtime bytes, `via_ir`, `optimizer_runs = 200`:

| Lever | Plan prototype | Review prototype |
|---|---|---|
| **A1a.** Fold `slashAggregators`' duplicated T1/T2 loops (`:1119-1195`) into one internal `_slashBatch(GI, batchId, aggregators, finalCID, minStakeAmt, s2Amount, bool t2)` | −471 B | −515 B |
| **A1b.** Make the 10 per-aggregator getters `internal` and add one view (below) | −355 B | −355 B |
| **A1c.** Make the `tier1Batches`/`tier2Batches` auto-getters `internal`. `getTier1Batch`/`getTier2Batch` already cover them | — | −214 B (both) |
| **Combined** | 23,542 B (margin 1,034 B) | 23,498 B (margin 1,078 B) |
| **Combined + Part B** | 23,551 B (margin 1,025 B) | 23,507 B (margin 1,069 B) |

**Rejected (measured):**
- folding T1/T2 `commit…`/`reveal…` into shared internals: **+177 B**, because `via_ir` inlines them
- folding `finalize…` the same way: **+166 B**
- lowering `optimizer_runs` to 1: only −76 B

Don't retry these.

**A1a — `_slashBatch`:**
- Keep the reason codes as `bytes32`: `AGG_T1_NO_SUBMISSION`, `AGG_T2_NO_SUBMISSION`, `AGG_T1_BAD_CONSENSUS`, `AGG_T2_BAD_CONSENSUS`.
- Keep every `AggregatorSlashed` event argument, the S2 partial slash with its `s2Amount > 0` guard, and the full-`minStake` bad-consensus slash.
- Keep the T1-then-T2 order.
- Behaviour must be identical, and the existing slashing tests must pass unchanged.

**A1b — `getAggregatorSubmission`:**

```solidity
function getAggregatorSubmission(uint _GI, TierKind tier, uint _batchId, address aggregator)
    external view
    returns (bool committed, bytes32 commitHash, bool submitted, bytes32 cid, uint votes);
```

- It replaces the public getters `t1/t2` × `SubmissionCID`, `Submitted`, `Votes`, `CommitHash`, `Committed`. The storage stays as it is; only the getters go.
- **`votes`** is the vote count for that aggregator's **own revealed CID** (`tNVotes[GI][batchId][cid]`), and 0 before a reveal. `t1Votes`/`t2Votes` are keyed by CID (`:66,85`), so per-arbitrary-CID lookup goes away. Nothing calls it today (PR #209 Decision 4).
- Callers to move:
  - **dincli:** `dincli/cli/aggregator.py:213,265,322,532` and `dincli/cli/modelownerd/aggregation.py:109,154`. These are the only Python callers.
  - **pytest:** `tests/test_aggregator_commit_retry.py:53`, which mocks `t1Committed`/`t2Committed` by name.
  - **foundry:** `AggregatorCommitReveal.t.sol:299,300,599,600` (`t1Submitted`, `t1SubmissionCID`), plus any other reader `forge build` flags.
- **Subgraph:** PR #29's mappings only `.bind()` `DINModelRegistry` and never call these getters. Only its bundled ABI goes stale, so post a note on PR #29 with the ABI change. Don't push to that branch.

**The margin after Part B is thin** (1,025–1,069 B against a 1,024 B fail line). Measure these two extra candidates and report them in the PR even if you don't take them:
- fold `tier1FinalizedAt`/`tier2FinalizedAt` into a view. `TreasuryForwarding.t.sol:275` reads `tier1FinalizedAt`
- merge tier-duplicated custom errors (`TC_T1/T2EmptyCommitHash`, `…AlreadyCommitted`, `…NoCommitFound`, `…RevealHashMismatch`) where the function already implies the tier

# Part E — #205: test-data dispute drain — PR 4

**Starts after PR 2 merges** (same contract and test files).

## Design (agreed, PR #209 Decision 3: #205 options 1 + 2)

- **Only the model owner's reveal can resolve.**
  - `resolveTestDataDispute` becomes owner-only.
  - A reveal that matches the stored commitment clears the dispute, and the bond is forfeited as today.
  - A reveal that doesn't match upholds it.
- **Silence loses.** If the owner doesn't reveal within `disputeWindowBlocks`, `closeExpiredDispute` (`:1540`) **upholds** the dispute instead of forfeiting the bond: bond back, `disputePenaltyBps` penalty via `_burnAndForward`, batch set to `pendingReassignment`.
- **Only batch auditors can open.** `openTestDataDispute` requires `isBatchAuditor(gi, batchId, msg.sender)` (a public mapping, `DINTaskAuditor.sol:230`).
- **Non-zero default bond.**
  - `disputeBondAmount` defaults to `100 * 1e18` DIN, matching `DINTaskCoordinator.disputeBond` (`DINTaskCoordinator.sol:149`).
  - It stays settable through the existing `setDisputeBondAmount` (`:1429`). Revisit the value alongside #155's tokenomics values.
- **Out of scope:** option 3 (committing `keccak256(K)` on its own) goes to #181/#38. The owner still judges disputes about their own test data, which is the trust assumption #181 tracks; say so in the NatSpec.

## Tests

- a non-owner `resolveTestDataDispute` reverts
- an owner reveal with the true `K` and plaintext hash clears the dispute
- the owner staying silent past the window upholds it via `closeExpiredDispute` (bond returned, penalty applied, reassignment pending)
- a non-batch-auditor `openTestDataDispute` reverts
- the deployed default `disputeBondAmount == 100 * 1e18`
- rewrite `test_resolveDispute_upheld_returnsBondAndPenalises` and `test_resolveDispute_upheld_blocksFurtherOpen` (`EncryptedTestData.t.sol:319,341`), which currently encode the attack
- the #205 failure scenario: an outsider with junk `K`, repeated after each reassignment, can no longer reduce `giRewardPool`
