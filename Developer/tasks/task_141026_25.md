## Background

There is no single command to verify a developer's machine is ready before starting work. Missing `foundry/node_modules` causes parallel test races on CI; wrong Python version, missing `torch`, bad `.env` — each of these has blocked contributors. The preflight check collects all these validations into one read-only command so the diagnosis is immediate.

---

## Preferred approach: `dincli system doctor`

Add a new `doctor` subcommand to `dincli/cli/system.py` (the `system` Typer sub-app already lives there). It runs all checks and prints one line per check:

```
[OK]      Python 3.12.6
[OK]      forge 0.3.2 / anvil 0.3.2
[OK]      solc 0.8.28 (via solc-select)
[OK]      foundry/node_modules present
[OK]      eth-account 6.3.0
[OK]      py-multibase 2.0.1
[MISSING] torch — run: pip install torch
[OK]      .env.sepolia_op_devnet found
[OK]      RPC https://... → chainId 11155420
[MISSING] IPFS_API_URL not set and no Filebase credentials — see Documentation/public/guides/ipfs.md
```

### Checks (in order)

1. **Python version** — `sys.version_info >= (3, 12)`. Print installed version. `[MISSING]` if below 3.12.
2. **forge / anvil installed** — `shutil.which("forge")` and `shutil.which("anvil")`. Run `forge --version` and print. `[MISSING]` with install hint if absent.
3. **solc 0.8.28** — `forge config --json | jq .solc_version` or parse `foundry/foundry.toml`. Report whether the required version is accessible. Warn if not.
4. **foundry/node_modules** — Check that `foundry/node_modules/@openzeppelin/upgrades-core` exists. `[MISSING]` with `cd foundry && npm ci` hint if absent. This is documented in `CLAUDE.md` as the source of parallel test flakiness.
5. **eth-account importable** — `import importlib; importlib.import_module("eth_account")`. Print version. `[MISSING]` if ImportError.
6. **py-multibase importable** — same pattern.
7. **torch importable** — same pattern. Note explicitly: `[MISSING]` is a warning (not a hard failure) since `torch` is only needed for the full test suite and reference service files, not for CLI operation.
8. **`.env` / `.env.<network>` present** — Check both `Path(".env")` and `Path(f".env.{network}")` exist in the repo root. `[MISSING]` with a pointer to the env file docs if absent.
9. **RPC endpoint answers** — Use the configured RPC to call `eth_chainId`. Print the returned chain ID. `[ERROR]` with the endpoint URL if the call fails or times out (5 s timeout).
10. **IPFS config resolves** — Call `resolve_ipfs_config()` from `dincli/services/ipfs.py`. `[OK]` if it returns a provider; `[MISSING]` with a pointer to `Documentation/public/guides/ipfs.md` if it raises or returns nothing.

### Exit codes

- Exit 0 if every check is `[OK]` or `[MISSING torch]` (torch is advisory).
- Exit 1 if any check other than torch is `[MISSING]` or `[ERROR]`.

### Flags

- `--no-color` — disable ANSI codes (auto-detected from `sys.stdout.isatty()`).
- `--network <name>` — override which `.env.<network>` and RPC are checked (defaults to the configured network).

## Notes

- This command is **read-only**: it must never install packages, modify files, or send transactions.
- The `[MISSING]` hint text should be the exact command to run, not a vague pointer. Example: `[MISSING] foundry/node_modules — run: cd foundry && npm ci`.
- Reuse `dincli/cli/utils.py`'s `CONFIG_DIR` / `CACHE_DIR` helpers where useful, but the command has no configuration of its own.
