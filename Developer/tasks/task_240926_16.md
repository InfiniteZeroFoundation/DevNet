# Part A — Ungrindable dispute-subgroup seed (#151, BL-11) — PR 1

## Context

`DINTaskCoordinator._assignFreshSubgroup` picks the fresh aggregator subgroup for an upheld S4 dispute by calling `_shuffleAddressArray`. That function seeds from `blockhash(block.number - 1)` (`foundry/src/DINTaskCoordinator.sol:553-561`). `resolveDispute` is `onlyOwner` and has no deadline. The model owner can therefore simulate the shuffle off-chain and call `resolveDispute(upheld=true)` only in a block that produces a subgroup favourable to them. This is BL-11, and it is the dispute-path instance of security-review finding H-2.

Issue #151 proposed a challenger-side commit-reveal. The review on #151 found that this moves the grinding rather than removing it. The challenger knows their own secret and chooses the reveal block, so they can grind the same way. They can also refuse to reveal and get a free re-roll. Part A implements the alternative agreed in that review: a **future-block seed fixed at `openDispute` time**. Nobody can predict it when the dispute opens, and once the seed block is mined nobody gets to choose anything.

While `resolveDispute`/`settleRecomputation` are both `onlyOwner`, the owner can still reject an upheld dispute outright. So this is not today's weakest link. It becomes load-bearing once adjudication moves off the owner, and BL-11 requires it before dispute resolution graduates past scaffold.

## Scope

### A1. Seed-taking shuffle helper

- Change `_shuffleAddressArray(address[] memory arr)` to take an explicit `bytes32 seed` and derive each swap index from `keccak256(abi.encodePacked(seed, i, arr.length))`.
- Keep the existing `autoCreateTier1AndTier2` call site (`:498`) behaviourally unchanged. Pass it `blockhash(block.number - 1)` explicitly for now. Replacing that seed is #156's job, and #156 should be able to plug its own seed source into this same helper without touching the dispute path again.
- Do **not** fork a second shuffle function.
- `DINTaskAuditor.sol:748` has the same pattern and is out of scope. Leave it alone.

### A2. Future-block seed on the `Dispute` struct

- Add seed state to `Dispute`: e.g. `uint64 seedBlock` and `bytes32 seed`. A zero `seed` means not locked.
- In `openDispute`, set `seedBlock = uint64(block.number) + disputeSeedDelay`.
- `disputeSeedDelay` is a new owner/DAO-settable `uint64` with a placeholder default in the 5–10 range. Follow the `disputeWindow`/`resolutionWindow` pattern and give it a setter with a non-zero guard.
- **Upgrade safety:** `DINTaskCoordinator` is not behind a proxy today, but check `Documentation/technical/storage_layout.md`. Update it if appending struct fields or new state variables changes anything recorded there.

### A3. Permissionless `lockDisputeSeed`

- New `lockDisputeSeed(uint _GI, TierKind tierKind, uint batchId)`, callable by **anyone**.
- Requires an open, not-yet-resolved dispute, no locked seed yet, and `block.number > seedBlock`.
- If `blockhash(seedBlock) != 0`: store `seed = keccak256(abi.encodePacked(blockhash(seedBlock), _GI, tierKind, batchId))` and emit an event.
- **The 256-block edge:** if `blockhash(seedBlock) == 0` (more than 256 blocks have passed), re-anchor with `seedBlock = block.number + disputeSeedDelay` and emit a re-anchor event. Never store or use a zero-derived seed.
  - This is not a re-roll lever. The party who dislikes the draw can't stop the challenger or any honest validator from locking it first.

### A4. `resolveDispute` / `_assignFreshSubgroup` use the locked seed

- `resolveDispute(upheld=true)` reverts with a new custom error if the seed isn't locked. `upheld=false` stays callable without a seed, since that path draws no subgroup.
- `_assignFreshSubgroup` passes the dispute's stored `seed` to `_shuffleAddressArray`. After this, the outcome of `resolveDispute` must not depend on the block in which it's called.
- Update the NatSpec that currently says "shuffled with the same blockhash-based entropy" (`:1343`) and the scaffold-wide comment block if it references the old entropy.
- **Trust caveat, write it down in the NatSpec:** on OP Stack, `blockhash` is sequencer-produced, so this design trusts the sequencer not to grind. That is acceptable for DevNet/testnet. VRF, or multi-party commit-reveal with a slashable non-reveal penalty, is the mainnet-grade follow-up and is out of scope here.

### A5. dincli — ABI only

- At `d321c2a`, `dincli` has no commands for the coordinator's dispute functions (`openDispute`/`resolveDispute`/`settleRecomputation`/`expireDispute`). Building that CLI surface is out of scope here.
- Refresh the bundled ABI in `dincli/abis/` if the coordinator ABI changes, and note the missing dispute CLI surface in the PR as a follow-up.

# Part B — Platform-resolved treasury forwarding (#152) — PR 2

## Context

Issue #152 as written is partly stale. PR #141 (issue #43) already forwards two of the three paths it lists:

- **Frivolous forfeit:** `DINTaskCoordinator.resolveDispute(upheld=false)` burns 50% and forwards 50% (`:1199-1210`).
- **Reward share:** `DINTaskAuditor.settleRewards`'s 5% share is forwarded (`:533-536`).
- **Tests:** both are covered by `foundry/test/TreasuryForwarding.t.sol` (7 tests).

The #152 review found the real gaps are elsewhere.

- **Stranded funds.** Four paths still only *count* the treasury share in `treasuryAccrued` and never transfer it, so those tokens are stuck in the task contracts:
  - `DINTaskCoordinator.settleRecomputation(confirmed=false)` (`:1292-1293`) — also sends the **full** bond to treasury instead of the 50/50 split every other forfeiture uses (MECHANISM_DESIGN §4 item 1).
  - `DINTaskAuditor.resolveTestDataDispute`, false dispute: the forfeited bond's treasury half (`:1477-1482`).
  - `DINTaskAuditor.resolveTestDataDispute`, upheld: the model owner's reward-pool penalty's treasury half (`:1496-1502`).
  - `DINTaskAuditor.closeExpiredDispute`: the expired bond's treasury half (`:1518-1524`).
  - Plus `settleRewards` with `treasuryAddress` unset: the 5% share is neither sent nor burned. The coordinator burns in the same situation.
- **Wrong trust boundary.** Both task contracts' `setTreasuryAddress` is `onlyOwner`, and the owner of a task contract is **the model owner**. A model owner can point it at their own wallet and collect the protocol's 5% share, half of every forfeited challenger bond, and half of the penalty levied on themselves when they lose a test-data dispute. Nothing in `DeployPlatform.s.sol` or `dincli` ever calls this setter on a task contract, so on a real deployment it's unset unless the one party with a reason to set it wrong sets it.

## Scope

### B1. Resolve the treasury from the platform

- Add `slashTreasury()` to `IDinValidatorStake` in `foundry/src/DINShared.sol`. `DinValidatorStake.slashTreasury` is platform-owned, and `DeployPlatform.s.sol:98` already wires it to the `DinTreasury` proxy. Both task contracts already hold `dinvalidatorStakeContract`.
- Remove `treasuryAddress`, `setTreasuryAddress`, and the auditor's `TreasuryAddressUpdated` event from **both** task contracts.
  - This deliberately departs from #152's acceptance criterion of a `dinTreasury` setter plus a `TreasuryUpdated` event. That criterion is superseded by the #152 review.
- If a separate protocol-fee treasury (distinct from the slash destination) is ever wanted, it gets exposed from a platform contract (e.g. `DinCoordinator`), never a task-level setter. That's out of scope here. Don't build it.

### B2. One forwarding helper, used everywhere

- One internal helper per contract, e.g. `_burnAndForward(uint256 amount)`:
  - burns 50% and sends 50% to `dinvalidatorStakeContract.slashTreasury()`,
  - burns the whole amount if `slashTreasury()` is unset, mirroring `DinValidatorStake.slash()` (`:646-652`).
- Duplicate it in each contract or put it in `DINShared.sol`, whichever fits the existing layout better. Say which in the PR.
- Route all six paths through it:
  - the two already-wired paths from PR #141,
  - `settleRecomputation(false)`,
  - the three `DINTaskAuditor` test-data-dispute paths.
- **Decision to flag, not guess:** the 5% `settleRewards` share is currently forwarded **in full**, not burned 50/50. It's a protocol fee, not a forfeiture. Keep it forwarded in full: route it through a forward-only variant of the helper (same unset-treasury burn fallback) rather than the 50/50 one, unless you see a reason otherwise. If you do, raise it on #152 first.
- Keep `treasuryAccrued` as an observability counter if it's still useful. Remove its stale "DinTreasury doesn't exist on develop" NatSpec and the remaining `TODO(task_210726_5)` comments:
  - `DINTaskAuditor.sol:54-63`
  - `DINTaskCoordinator.sol:1078-1081`
  - `DINTaskCoordinator.sol:1292`

### B3. dincli / scripts

- Refresh the bundled `DINTaskCoordinator`/`DINTaskAuditor` ABIs in `dincli/abis/`.
- Grep `dincli/` and `foundry/script/` for any `setTreasuryAddress` / `treasuryAddress` reference and remove it. None existed at `d321c2a`; confirm that's still true after re-pulling.
